# Product blueprint

## 1. Продуктовая суть

Тип: privacy-first AI web/PWA dashboard. Первый пользователь — человек, который хочет понять, с кем из уже знакомых стоит продолжить общение. Работа начинается с ручного импорта разрешённого архива.

Первый полезный момент: после импорта пользователь видит отсортированный список контактов с коротким объяснением «почему сейчас». Основное повторяемое действие: открыть карточку, проверить факты и адаптировать черновик.

Не обещаем «найти идеальную пару». Обещаем уменьшить хаос в уже имеющихся диалогах и помочь написать уважительное сообщение.

## 2. MVP-границы

Входит: регистрация, личное рабочее пространство, импорт поддержанного архива, парсинг и нормализация, список диалогов, карточка контакта, сигналы интереса/давности/тем, объяснимая рекомендация, черновик сообщения, ручное редактирование, удаление данных, экспорт результата.

Не входит: автоматическая отправка, scraping, OAuth к соцсетям, чтение live-чатов, поиск людей в интернете, скрытое профилирование, распознавание чувств как факт, платежи, командные роли, marketplace.

## 3. Потоки

1. Новый пользователь: welcome → согласие с правилами → создать workspace → импортировать архив → показать прогресс → список диалогов.
2. Возвращающийся: список → фильтр «требует внимания» → карточка → объяснение → черновик → копировать вручную.
3. Ошибки: неподдержанный формат, частично повреждённый архив, пустой архив, недоступный AI, превышение лимита. Всегда сохраняем понятное состояние и не теряем исходник без предупреждения.
4. Удаление: удалить один диалог, импорт или весь workspace; перед удалением показать объём и последствия.

## 4. Маршруты

`/` welcome; `/onboarding`; `/imports`; `/imports/:id`; `/conversations`; `/conversations/:id`; `/settings/privacy`; `/settings/account`; `/help`.

Будущий white-label: `/w/:workspaceSlug/...` без копирования доменной логики. Бренд, правила и лимиты — конфигурация workspace, а не отдельная ветка продукта.

## 5. Объяснимая рекомендация

Рекомендация строится из наблюдаемых признаков: свежесть последнего сообщения, взаимность, наличие вопроса/незавершённой темы, повторяющиеся темы, пользовательские сигналы и качество данных. На экране показываем 2–4 причины, дату/источник каждой причины и уровень уверенности. Формулировка — «может быть полезно написать», не «человек точно заинтересован».

## 6. Данные

Сущности: `User`, `Workspace`, `Membership`, `Import`, `Conversation`, `Participant`, `Message`, `ContactProfile`, `Recommendation`, `Draft`, `AuditEvent`, `DeletionRequest`.

Ownership: каждый объект принадлежит workspace; пользователь видит только свои workspace; будущий оператор клуба видит только разрешённые workspace/member-scoped данные. Raw archive — отдельный зашифрованный объект с TTL, нормализованные сообщения — отдельная таблица с минимальным набором полей.

## 7. API-границы

`POST /imports` создаёт импорт; `GET /imports/:id` возвращает статус; `GET /conversations`; `GET /conversations/:id`; `POST /conversations/:id/recommendation`; `POST /conversations/:id/drafts`; `PATCH /drafts/:id`; `DELETE /imports/:id`; `DELETE /workspaces/:id`.

AI вызывается только сервером через адаптер `ModelProvider`. Вход — нормализованный минимальный контекст; выход — строгая схема JSON, сохранённая вместе с версией промпта и модели. Клиент никогда не получает ключ провайдера.

## 8. Будущий white-label

Ядро: workspace/tenant, feature flags, policy config, brand config, usage limits, provider registry и audit trail. Изоляция данных — на уровне запросов и тестов; для крупных клиентов возможна отдельная БД позже. Админ-клуба не должен видеть личные сообщения без явного разрешения участника; по умолчанию клуб получает только агрегаты и opt-in функции.

## 9. Метрики и критерии готовности

MVP: ≥80% импортов из поддержанного формата проходят без ручного вмешательства; пользователь понимает причину рекомендации в usability-тесте; 0 автоматических отправок; удаление действительно удаляет все копии в пределах заявленного SLA; AI-вывод валиден по схеме; каждый доступ к данным аудируем.

## Требует решения пользователя

- Первый формат архива и максимальный размер файла.
- Юридическая юрисдикция, срок хранения и допустимый AI-провайдер.
- Нужен ли аккаунт уже в первом прототипе или достаточно локального single-user режима.
- Какой тон черновиков допустим и какие темы всегда запрещены.
