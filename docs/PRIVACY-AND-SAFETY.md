# Приватность и безопасность

## Базовые правила

1. Только пользовательский upload и подтверждение права обработки.
2. Нет доступа к чужим аккаунтам и нет фонового сбора.
3. Нет автоматической отправки: draft заканчивается ручным копированием.
4. Минимизация: не импортировать вложения, аватары и метаданные без отдельного решения.
5. Шифрование in transit/at rest; секреты только в secret manager будущей среды.
6. Raw archive удалять после успешного разбора или по короткому TTL; политика должна быть измеримой.
7. Удаление — каскадное и проверяемое, включая очереди, storage, backups по заявленной политике.

## Угрозы

Prompt injection в сообщениях, утечка PII через логи, cross-tenant access, IDOR, вредный или манипулятивный текст, повторная обработка удалённых данных, слишком широкие админ-права, подмена файла, DoS большим архивом.

## Контрмеры

Изоляция workspace в каждом запросе; deny-by-default authorization; лимиты размера/строк/времени; антивирус/тип-файл; redaction логов; schema validation; retries без дублирования; audit events; threat-model review до beta; abuse and safety tests на реальных обезличенных сценариях.

## Данные для разработки

Только синтетические фикстуры. Реальные архивы не коммитить, не отправлять в issue/PR и не использовать в тестах без отдельного согласия и плана удаления.
